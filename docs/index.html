64Gram RPM packages for Linux

Unofficial RPM builds of 64Gram, the x86_64 fork of Telegram Desktop. One package installs on Fedora, RHEL 8+, AlmaLinux, Rocky Linux and openSUSE — and it replaces telegram-desktop cleanly instead of fighting it for your tg:// links.

  • x86_64
  • no dist tag
  • rebuilds weekly
  • GPL-3.0-or-later

Install

Download the latest RPM Source repository
# grab the newest package, then install it locally sudo dnf install ./64gram-<version>-2.x86_64.rpm

The installed command is 64gram, the app menu entry is 64Gram. Upgrades are the same command with a newer file — there is no repository to add.

It replaces the official client on purpose. The package declares Obsoletes: telegram-desktop, so dnf removes the stock client when you install it. Without that, both packages advertise x-scheme-handler/tg and which app opens a tg:// link becomes a coin flip. Your chats stay in ~/.local/share/TelegramDesktop, so switching back to the official build later does not lose data.

Why this package exists

  • 64Gram ships Linux as a raw .zip. No RPM, no repo, no desktop entry — you unpack a binary and get nothing in the app menu. This packages that binary properly.
  • One client per link scheme. Ties up tg://, tonsite:// and ton:// in a single owner.
  • No dist tag on purpose. The binary is statically linked against Qt, OpenSSL, ffmpeg and WebRTC, so a single package serves RHEL/Alma/Rocky 8+, Fedora and openSUSE instead of one build per release.
  • Real desktop integration. AppStream metadata, D-Bus activation, hicolor icons at seven sizes, and the XDG app id the binary actually asks for (io.github.tdesktop_x64.TDesktop) — so the window maps back to its launcher, the tray icon resolves, and the PulseAudio stream is tagged correctly.

Runtime dependencies are only libX11, libxcb and libxkbcommon — everything else is already inside the binary.

How the packages are built

upstream release feed ──▶ new version? ──no──▶ stop │yes ▼ download the official Linux .zip ──▶ rpmbuild ──▶ install in a clean Fedora container ──▶ GitHub release

A GitHub Actions workflow polls the upstream release feed every Monday at 06:00 UTC and publishes only when the version is genuinely new. Before anything is released, the RPM is installed with dnf inside a fresh Fedora container and checked for its Provides:, Obsoletes: and tg:// handler registration — so a broken package fails the build instead of reaching you.

Questions

Is this an official 64Gram or Telegram release?

No. It is a third-party repack of the binary the 64Gram project publishes. Nothing is compiled here and nothing is modified — the packaging is the only original work. 64Gram itself is GPLv3 with an OpenSSL exception, copyright its authors.

Will it work on CentOS Stream, AlmaLinux or Rocky?

Yes — the release carries no dist tag and does not depend on any Fedora-specific library version, so the same RPM installs on RHEL-family 8 and newer. On EPEL-only systems you may need libxkbcommon from the base repo, which is already present there.

Can I keep the official Telegram Desktop installed too?

Not recommended, and dnf will not let you by default: this package obsoletes it. Two clients claiming x-scheme-handler/tg makes clicking a link unpredictable. If you want both, use one as a Flatpak.

How do I uninstall and go back?

sudo dnf remove 64gram, then sudo dnf install telegram-desktop. Your message history and session stay in ~/.local/share/TelegramDesktop throughout.
